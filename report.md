## 2. Контракт і CP-01

`POST /api/incidents` приймає окремий `CreateIncidentRequest` лише з `title`, `description`, `severity`, `occurredAtUtc`. Сервер перевіряє довжину title до 160 і description до 4000 символів **до** `Trim()`, після одного `Trim()` відхиляє порожні обовʼязкові поля. Severity має бути визначеним значенням enum. Дата обовʼязкова й не може бути пізнішою за один зафіксований серверний `now + 5 хвилин`; перед збереженням зміщення нормалізується до UTC.

Для High/Critical description після `Trim()` повинен мати щонайменше 40 символів: 39 дає 400 з `errors.description`, 40 проходить. Повторне створення не-Closed інциденту з тим самим title після `Trim()` у тому самому регістрі дає 409 Problem Details. Closed не блокує новий запис; title в іншому регістрі не вважається тим самим.


Перевірка чи прочитаєте смайлік смайлік смайлік

Сервер сам визначає `Id`, `OwnerUserId` (навчальна Аліса Коваль), `Status=New` і audit-часи; у request DTO цих полів немає. Успіх повертає 201 з `CreatedIncidentResponse` без внутрішніх полів entity. Некоректний DTO повертає 400 `application/problem+json` з ключем поля. SQL і stack trace не потрапляють у відповідь.

Реалізація: `src/SecureLab.Api/Scaffolding/Lab02Endpoints.cs`. Контракт підтверджують `Lab02ContractTests` (T-01, T-02, T-03, T-06, T-09).

## 3. Security-сценарій і CP-02/CP-03

**Контекст.** Браузер передає недовірені `q` і `sortBy` до `GET /api/incidents/search`. Перевірка виконувалася лише локально на штучних seed-даних, після `--reset-database`.

**Стан до, CP-02.** У commit `fa96143` `MapLab02Endpoints` додавав `q` до SQL-тексту й передавав його у `FromSqlRaw`. Для `sortBy` був fallback `_ => sortBy`. Звичайний запит `q=USB` повернув один відповідний запис, а запит відсутнього значення — `[]`. Дозволений read-only контрольний ввід, якого немає в даних, повернув усі пʼять seed-записів. Легітимний `O'Brien` дав 500 з узагальненим Problem Details; SQL і stack trace у HTTP-відповіді не було. Першопричина — змішування значення клієнта зі структурою SQL.

**Виправлення, CP-03.** У commit `fe15899` фільтр побудований через LINQ і `EF.Functions.ILike`; шаблон передається як параметризоване значення. Символи `%`, `_` і `\` екрануються для буквального пошуку. `sortBy` вибирає лише серверні гілки `createdAtUtc`, `severity`, `status`; невідоме значення дає 400 з `errors.sortBy`. Severity/status сортуються за визначеними рангами, далі за `Id`; після сортування діє `Take(50)`. Різницю коду можна переглянути командою `git diff fa96143..fe15899 -- src/SecureLab.Api/Scaffolding/Lab02Endpoints.cs`.

**Повторний прогін S-02 на тому самому seed:**

| Запит | До виправлення, S-01 | Після виправлення, S-02 |
|---|---|---|
| A: звичайний `q=USB` | 200, один запис `…0005` | 200, той самий запис `…0005` |
| B: відсутнє значення | 200, `[]` | 200, `[]` |
| C: той самий read-only контрольний ввід | 200, усі пʼять seed-записів | 200, `[]` |
| D: легітимний `O'Brien` | 500 `application/problem+json` | 200, один запис `…0004` |
| E: буквальний `%` | Не перевірявся | 200, `[]` |
| F: `sortBy=price` | Не перевірявся | 400 `application/problem+json`, `errors.sortBy` |

Повний контрольний рядок і SQL не дублюються в звіті; запит є у `tests/http/lab-02-checks.http`. Сценарій C після виправлення не розширює множину. Автотест `Lab02SearchTests.S02_ControlInput_DoesNotExpandResults` повторює цю перевірку.

Тестовий збіг `"SELECT "` лише перевіряє відсутність SQL у Problem Details. Це огляд подібних raw-SQL місць для рівня «Добре».

## 5. Обмеження і висновок

Ручні HTTP-відповіді перевірено для S-01, S-02, T-04 і T-05. T-01, T-02, T-03, T-06, T-09 підтверджені автоматичними тестами, без окремого ручного HTTP-протоколу. Попередня перевірка дубліката через `AnyAsync` дає 409 у звичайному випадку, але без обмеження або транзакції в БД не гарантує інваріант за одночасних POST. Навчальний власник не замінює автентифікацію. Пошук повертає не більше 50 результатів без пагінації.

Вимоги до контракту, 400/409, вразливого й виправленого сценаріїв SQLi, позитивної регресії та огляду A-01 реалізовано й локально перевірено. До подання ще потрібно додати групу, створити окремий коміт цього звіту, перейменувати гілку, створити тег `v0.2.0`, опублікувати гілку й тег та перевірити доступ викладача.
